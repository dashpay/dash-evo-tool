Tokens in the Identity Hub — wireframes

Dash Evo Tool, 2026-10-28. Companion to README.md. Mid-fi, same visual system as the 2026-10-01 usernames canvas; light and dark themes mirror DashColors light/dark roles (toggle top right). Hover, focus (Tab) and open-menu states are live. Frames marked MVP ship in phase 1; P2/P3 later. No administrative token action (mint, burn, freeze, pause, price, config) appears anywhere in the hub; the only link to them is the Power-only "Manage in Tokens screen" menu item (optional).

T0

Information architecture: before and after

  • Today every token question goes through Tokens › My Tokens, a token-first table that lists all identities per token, with issuer actions mixed into holder actions.
  • After: the hub gets an identity-first Tokens tab (holder jobs only). The Tokens screen keeps every admin flow; nothing moves, nothing is removed.

T1

Hub › Tokens tab, populated

AlexPriyaMVP
  • Tab bar becomes Home · Contacts · Tokens · Profile (supersedes the 3-tab strip in 2026-10-01 U1/U2). The tab shows a count only when a claim is waiting, never the token count.
  • One row per tracked token, for the selected identity only. Balance uses the token's own decimals and alias (Amount::from(&IdentityTokenBalance)). Sorted: claimable first, then balance descending, zeros last.
  • Row actions: Send (holder has a balance and the token is transferable) and Claim (a distribution this identity can take). Everything else lives under •••. The menu is shown open on row 2 to demo it.
  • "Last updated" is the time of the last successful balance sync; Refresh re-registers the watch set and forces a pass (existing QueryMyTokenBalances).

T3

Loading and error

AlexMVP
  • Left — first visit, nothing synced yet: skeleton rows keep the layout stable; one spinner line. Refresh is disabled while a pass is in flight (single-flight guard; TokenBalanceRefreshInProgress is not an error to the user).
  • Right — refresh failed: known balances stay on screen with their "Last updated" time; the error is inline, says what happened and what to do, and offers the retry where the eye already is. Never a blocking modal, never an empty list.

AlexPriyaP2
  • Opened from a row (click, Enter, or ••• Token details). Answers: how much do I have, can I send it, is anything waiting for me, who issued it. Plain words; IDs are copyable handles, not jargon.

T7

Receiving tokens

AlexMVP
  • Tokens are sent to an identity, exactly like Dash on Platform, so the Tokens tab reuses Home's Receive dialog with one extra sentence. No new "token address".
