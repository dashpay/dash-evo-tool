SCENE 18 | Who may change the rule
SCREEN: Authorized to change rules selector and all three boolean switches. Use an example before/after diagram, not a signed update.
CONTROLS: rule-admin, allow-performer-to-no-one, allow-admin-to-no-one, self-changing-admin
VOICE: The second selector answers a different question: who may change this permission rule later? For an unchangeable rule, decide both selectors before registration.

SCENE 30 | Distribution controls: what they do
SCREEN: Distribution, enable/disable Perpetual, Pre-Programmed, Once-per-identity. Explain practice-preview status and final all-off policy.
CONTROLS: perpetual-enable, scheduled-enable, once-enable, distribution-vs-initial-supply, claim

SCENE 36 | StepDecreasing
SCREEN: StepDecreasing. StepCount2, numerator1, denominator2, startblank, initial100, minimum10, maxintervalcount3, trailing10. Overlay f0..8=100,100,50,50,25,25,12,12,10.

SCENE 37 | Stepwise
SCREEN: Stepwise AddStep3times. StartStep/Amount0:10,3:5,5:0. Add/remove extra practice row. Overlay f0..6=10,10,10,5,5,0,0.
CONTROLS: stepwise-start, stepwise-amount, add-step, remove-step, duplicate-step
VOICE: Stepwise lets you write an explicit table. Add three steps: start zero with amount ten, start three with amount five, and start five with amount zero. The latest step whose start has been reached supplies the amount. That gives ten through index two, five at indices three and four, and zero from five onward. Zero stops future emissions; it does not erase existing balances. Add Step creates a row, and Remove deletes it from this draft. Use at least two different start indices. A duplicate index replaces an earlier value rather than creating a second payment. A campaign with distinct reward phases fits this function well.

SCENE 38 | Linear
SCREEN: Linear a2,d1,sblank,b10,min0,max20. Overlay formula2k+10 clipped20; f0..5=10,12,14,16,18,20.
CONTROLS: linear-a, linear-d, linear-s, linear-b, linear-min, linear-max
VOICE: Linear changes the reward by a constant amount each period. SCENE 39 | Polynomial
SCREEN: Polynomial a1,m2,n1,d1,sblank,o1,b0,min0,max100. Overlay (k+1)^2; f0..5=1,4,9,16,25,36.
CONTROLS: polynomial-a, polynomial-m, polynomial-n, polynomial-d, polynomial-s, polynomial-o, polynomial-b, polynomial-min, polynomial-max
VOICE: Polynomial supports a power curve. Enter a equals one, m equals two, n equals one, and d equals one. Leave s empty. Set the argument offset o to one, the added amount b to zero, minimum zero, and maximum one hundred. Here m divided by n is the exponent, so this recipe is k plus one, squared: one, four, nine, sixteen, twenty-five, thirty-six. The offset moves the input inside the power; b adds to the result. Fractional powers involve rounding, so do not assume every recipe produces exact squares. A positive exponent of one belongs in Linear. Quadratic growth is useful only when you deliberately want accelerating rewards and have bounded their cost.

SCENE 40 | Exponential
SCREEN: Exponential a10,m1,n1,d1,sblank,o0,b0,min0,max100. Overlay 10exp(k), floor/clamp; f0..5=10,27,73,100,100,100.
CONTROLS: exponential-a, exponential-m, exponential-n, exponential-d, exponential-s, exponential-o, exponential-b, exponential-min, exponential-max
VOICE: Exponential grows or declines much faster. Enter a ten, m one, n one, d one, leave s empty, set o zero, b zero, minimum zero, and maximum one hundred.
